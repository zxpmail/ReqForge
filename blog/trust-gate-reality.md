# 信任门：微小团队在AI时代的身份困境

读OpenFab那份"可信AI软件工厂"方案的时候，你觉得逻辑闭环、无懈可击。Spec Cycle七步流水线，AI-BOM记录出身，in-toto/SLSA签名溯源，N-of-M人工签核，任何人可离线复验。

然后你回到自己的3人团队，发现第6步"信任门"根本推不动。

知道做不到，不是知识问题，是**身份问题**。

你把"加一道审批"翻译成了"我要变成严谨的软件工程师"，大脑直接报警——这跟你在公司会议上想提个建议却被大脑翻译成"社交自杀"，是同一个机制。

---

## 一、理想蓝图长什么样

先给没看过原文的人补个背景。OpenFab的核心流程：

| 步骤 | 内容 | 产出 |
|------|------|------|
| **意图** | 提自然语言需求 | 用户故事 / PRD 片段 |
| **Spec** | 编译成机器可检查的契约 | 形式化 Spec（Clarify / TLA+） |
| **生成** | AI写代码，同时记录AI-BOM | Agent身份、模型、Prompt哈希 |
| **验证** | 在策略沙箱里跑验收测试 | 测试报告 |
| **签名** | 生成in-toto/SLSA认证并用ed25519签名 | 密码学签名 |
| **信任门** | N个独立人里的M个进行人工签核，且永不自批 | 签核记录 |
| **溯源** | 入仓，供任何人独立复验 | 可复现构建包 |

看着没毛病。密码学背书，问责清晰，逻辑闭环。

但问题就出在第6步。

---

## 二、信任门在微小团队面前是堵墙

> "N个独立的人"——如果团队只有3个人甚至1个人呢？

凑不齐。硬凑的结果就是流于形式：群里发个"代码看了没问题的扣1"，三个人分别扣完1，就算完成了"多人签核"。出事了翻聊天记录，"你也扣了1，凭什么怪我？"

这不叫信任门，这叫**甩锅链**。

文章自己承认了最核心的问题：**签名≠安全，可复现≠可信。** 签名只能证明"谁、什么时候、签了什么"，证明不了"源码本身没有后门"。

那微小团队怎么办？凑不齐三个人，就不配做可信软件了吗？

---

## 三、现实更残酷：我们是在收集安慰，不是在收集证据

更扎心的是第二个现实：**AI迭代速度碾压了一切长周期的验证流程。**

上周的SOTA模型这周就被超了。昨天写的Spec今天因为OpenAI发了新API就得全改。形式化验证需要几周，AI生成代码只要几秒。

在这种节奏下，你让团队停下来搞严格的溯源追踪，就相当于让F1车手在比赛中下车检查轮胎——理论上正确，实际上等于退赛。

于是行业里真实发生的就变成了**"三不政策"**：

- **不追溯** —— 编译通过UT跑通就合
- **不审计** —— CVE公布速度赶不上AI写代码速度
- **靠运行时硬扛** —— 唯一的信任门叫"监控报警"，没报500就是可信的

所谓"AI可信工厂"，最终大概率沦为年终PPT上的一页：*AI-BOM覆盖率90%+*，*人工签核率100%+*。

> 你仔细想想：我们建信任门，到底是因为有真实证据证明它拦住了攻击，还是因为"看起来应该这样"？
>
> 如果是后者——你就是在收集安慰，不是在收集证据。

产品方法论里区分了 **Hope** 和 **Belief**。Hope不以任何亲身经历或用户数据为基础，Belief来自真实反馈。区别只有一个：**Belief能掏出收据，Hope只能掏出想象。**

把这句话翻译到软件工程领域：

- 如果你建信任门是因为"有过真实攻击被它拦住"——那是 **Belief**。
- 如果你建信任门是因为"规范的软件工程就应该这样"——那是 **Hope**。

而我们大多数人，是在用Hope写KPI。

## 四、AI验证AI：希望的工业化生产

有人提出替代方案：既然凑不齐N个人，那就用N个不同的AI模型来做"硅基签名者"——让Claude检查GPT的代码，让本地小模型做规则扫描，三个AI交叉验证。

听起来很聪明。但你想想：用AI去验证AI，本质上是什么？

**是用一个"不可信"去证明另一个"不可信"**。

如果攻击者通过提示词注入污染了Spec，或者利用了所有主流模型的共同幻觉盲区，三个AI会异口同声地说"代码没问题"，然后一起被骗过去。

更可怕的是——AI不仅能帮你做产品，还能生成"看起来像证据的东西"。

三个AI模型交叉验证通过的报告，那不是验证通过，那是**希望的工业化生产**。它看起来像证据，但零次真实攻击拦截记录。

产品方法论里有一句警告：**AI不是帮你做产品——是帮你更快、更精致地骗自己。**

放在信任门这件事上：AI也不是帮你做安全——是帮你更快、更精致地生产"看起来做了安全"的报表。

## 五、真正的保命法则：就4条

把宏大叙事放一边。微小团队在AI时代写代码，真正靠得住的就这4条**"抗揍"法则**。

### 1. 小步快跑——把变更拆到一口能吃下

别让AI一口气生成1000行代码让人Review。强制AI把每次变更拆成原子粒度，人只需要看"Spec变了什么"（10行文本），而不是"代码变了什么"（1000行）。

降低认知负担，才是对人性最大的尊重。

```python
# ❌ 坏：AI一次性改1000行 → 人根本看不完
ai generate "add user auth, profile, search, and pagination"

# ✅ 好：每次只改一件事
ai generate "add password hashing to User model"
ai generate "add login endpoint with JWT"
ai generate "add profile GET endpoint"
ai generate "add search query with pagination"
```

### 2. 戴紧箍咒——默认给最低权限

AI生成的代码，管你写得天花乱坠，运行时直接上沙箱。不允许访问外网，不允许写磁盘，不允许执行系统命令。

信任门不问你"这代码安全吗"，而是问**"这代码被允许做什么"**。把信任交给基础设施策略，而不是代码本身。

```yaml
# seccomp profile for AI-generated code
seccomp:
  defaultAction: SCMP_ACT_ERRNO
  syscalls:
    - names: [read, write, exit, exit_group]
      action: SCMP_ACT_ALLOW
    # 坚决不放开：open, execve, connect, fork
```

### 3. 一键撤销——承认会看走眼，但能秒回滚

就一个人签字，看走眼了怎么办？承认。但代价要趋近于零。

灰度发布 + 实时异常检测 + 自动熔断。坏人进来了，30秒内踢出去。

**真正的信任是"出事能扛"，不是"永远不出事"。**

```bash
# 出事之后的30秒
kubectl rollout undo deployment/api -n production
# 或者其他更简单的：
rsync -avz --delete ./last-known-good/ ./production/
```

### 4. 物理隔离——用密码学替代人性

凑不齐N个人，但可以凑齐N个物理环境。开发机一把私钥提Spec，CI/CD的HSM另一把私钥做签名。

攻破你笔记本容易，同时攻破笔记本 + 云端HSM + KMS？成本高出几个数量级。

**把信任交给密码学，而不是交给"大家自觉"。**

```
                    +----------------+    +------------------+
  dev laptop key →  │  sign spec     │    │  HSM / KMS key   │
                    +----------------+    +------------------+
                            │                      │
                            ▼                      ▼
                    spec署名                 签名验签准入
                    (证明谁提的)             (证明环境可信)
```

## 六、收个尾

回到最开始那个问题：你推信任门，到底是为了什么？

是为了十年后回头看，这真的让软件更可信了——

还是为了年底PPT上有一页"AI-BOM覆盖率90%+"？

如果是后者，它只能保你过审计。同行的眼睛给你三年热度，用户的眼睛给你十年价值。

而真正的用户——那些被漏洞攻击、被数据泄露伤害的人——他们不在乎你的PPT上有几行签名。

回过头看OpenFab那套理想，我依然觉得它方向是对的。就像莱特兄弟的木头飞机告诉人类"飞起来需要机翼和动力"，它是指南针，不是操作手册。

但对于今天95%的普通业务系统，"可信"的及格线根本不是什么防APT攻击、防供应链投毒，而是：

> **别删库 + 能回滚 + 出了事30秒内有人（或机器）扛得住。**

理想是用来仰望的，KPI是用来糊口的，而真正保命的，永远是那个一键回滚的按钮。

能把上面4条落到实处的团队，在AI时代写代码的底气，已经比市面上90%只顾着吹"AI覆盖率"的团队硬气多了。

**面子是工程里最贵的成本**——它不计入财务报表，但它吃掉一切。为了面子硬撑一套跑不动的流程，比"承认现实、先跑起来再说"贵一万倍。

你选哪个？

## Abstract (English)

Long-horizon agentic reinforcement learning has advanced along two largely separate lines: *optimizers* that stabilize asynchronous updates, and *collaboration interfaces* that share context among agents. Between them, a dataflow question is often left unnamed: after trajectories are produced, which experiences may approach the base policy, at what depth, and under what isolation rules may they update \(\theta\).

We call this layer **experience admission** (also *experience routing*). We separate claims into **C1** (diagnosis), **C2** (architectural hypothesis), and **C3** (tunable design placeholders). Novelty is pinned on four irreducible primitives (P1–P4)—default no deep-read rights; quarantine \(\neq\) deletion; deep-read \(\neq\) admission; \(D_{\mathrm{adm}}\subsetneq D_{\mathrm{all}}\)—rather than a new scoring rule. We specify a preregistered falsification protocol under which the position can be rejected, and note that a runnable instantiation exists (Appendix C). This paper does **not** claim large-scale LLM reinforcement-learning gains.

**Hypothesis-level claim:** in multi-worker agentic RL, the bottleneck is often not making more models see each other, but letting experience reach the base policy in a layered, isolated, and low-frequency manner.

## 摘要

长时程智能体强化学习主要沿两条线推进：优化器（异步、单 rollout、裁剪等）与协作界面（共享上下文、文件可见性等）。二者之间常缺一层被单独命名的问题：**轨迹生成之后，哪些经验有资格接触基座策略，接触多深，在何种隔离下可更新 \(\theta\)**。

本文称之为**经验准入控制（experience admission / experience routing）**——rollout 与基座更新之间的数据流层，不是优化器附属技巧，也不是 PER 的局部重加权。主张分三层：**C1 诊断**、**C2 架构假说**、**C3 设计占位**；C1 不蕴含 C2。新意落在 **P1–P4**（§3.6），并给出**预注册失败条件**下的可证伪协议。文末附录记录了该协议的可运行实例；**主文不把附录数字当作已验证的方法主结果**，也不报告大规模 LLM 训练收益。

**假说级中心判断：** 多 worker 下，瓶颈往往不在让更多模型彼此看见，而在让经验以**分层、隔离、低频**方式抵达基座策略（见第 7 节）。

**关键词：** experience routing；experience admission；agentic RL；dataflow；prioritized experience replay；falsification protocol  

**Keywords:** experience routing, experience admission, agentic RL, dataflow, prioritized experience replay, falsification protocol

## 引言

长时程智能体强化学习正在进入一个新的阶段。随着大语言模型越来越多地被用于代码、工具调用和多步决策，训练系统已经不再只是“对一个静态策略做短链条后训练”，而是在处理长度高度不均、反馈稀疏、工具交互昂贵且错误模式异质的轨迹集合。在这一背景下，现有工作主要沿两条方向推进。第一类工作关注**如何稳定地训练**：例如异步 actor-learner 设计、单 rollout 更新、价值模型辅助和 token 级裁剪，试图缓解同步组采样在长轨迹场景中的低效与不稳定。第二类工作关注**如何更顺滑地协作**：共享上下文、跨 agent 文件可见性和会话继承降低了交互期的 handoff 成本，使多智能体在实际工作流中更容易配合。

但这两类进展之间，仍常缺少被单独命名的一层。优化器回答：**梯度何时、以何形式应用**。协作界面回答：**交互期如何共享工作上下文**。二者都不直接回答：**轨迹已生成之后，谁可读、读多深、何时可影响 \(\theta\)**。我们将后者称为经验准入控制——它与 replay / safety filter 相邻，但不应被默认吞没为实现细节。

为何值得单独讨论（而非“已证明必须开题”）？因为在长时程、异步、多 worker 设定下，失败模式不完全等于“优化器不够好”：吞吐上升仍可能无差别暴露噪声与高风险轨迹；协作改善也不自动给出隔离与准入规则。**训练稳定性**与**经验准入语义**相关但不等同。已有工作在 priority sampling、offline 保守、shielding、异步 actor-learner、data curation 等层面触及此空间，却多停在 loss / sampling / 约束，而缺少一套显式**准入语义**（见 §3.6 不可约条目）。

本文将该立场称为 experience admission / routing：新意不在新打分函数，而在把接触顺序、观察深度、隔离边界与准入条件提升为可叠加于 SAO [1]、GRPO [2] 等优化器之上的数据平面。主张分三层——C1 诊断张力；C2 架构假说；C3 设计占位——详见第 2 节。本文是立场文：把对象钉清、把预注册失败条件下如何被否掉写清；可运行实例仅作附录记录，不在主文扮演“已实证有效”的角色。

后文结构：主张分层 → 相关工作与不可约语义 → 形式化草图 → 架构判断 → 证据纪律 → 可证伪协议 → 反对意见与未来工作。

## 1. 本文贡献与非主张

本文定位为 **arXiv 技术立场预印本**（Technical Position），不是经验方法论文，也不报告大规模 LLM agentic RL 主结果。目标是：把散落在 replay / filtering / shielding 中的问题钉成可命名对象，并写清其在何种预注册条件下应被拒绝。

**第一项贡献：问题重述。** 在长时程、多 worker、异步的 agentic RL 中，除“如何稳定更新”和“如何协作”外，还存在第三层：**经验准入控制**——轨迹生成后谁可读、读多深、何时可影响 \(\theta\)。这是数据流组织问题，不是 sampling / loss 的附属实现。

**第二项贡献：可组合立场与不可约语义。** 准入层叠在优化器 \(\mathcal{A}\) 之上，不替代 SAO [1] / GRPO [2]。新意压在 §3.6 的 P1–P4（默认无深读权；隔离≠删除；深读≠准入；\(D_{\mathrm{adm}}\subsetneq D_{\mathrm{all}}\)），而非具体指纹公式。

**第三项贡献：可证伪协议。** 指纹维数等仅为占位；第 7 节给出 A/B（及与 PER 对照）及**预注册失败条件**——含条件 5：路由代理信号与深读后学习增益的秩相关不显著时强形式判负。

主文贡献止于此三项。协议的可运行实现与玩具尺度执行记录放在**附录 C**，仅说明对象可以落地，**不计入本文贡献清单，也不构成方法主结果。**

**非主张：** 不声称新算法有理论保证；不声称 Tutti 类产品可作 RL baseline；不把占位参数当最优；不声称强形式覆盖黑盒 API；不声称完成大模型 LoRA / 云端权重更新；**不把附录执行记录中的百分比写成大规模算力或主会级实证结论。**

价值标准：是否把 P1–P4 钉牢，是否写清如何被否掉——而不是是否已给出最优方法或弹药级主结果。

## 2. 问题界定与主张层级

### 2.1 三个常被混写、但应分离的问题层

为了避免把不同性质的问题混为一谈，本文将 agentic RL 中常见的讨论拆成三个层次。

第一层是**优化层**。这一层关心的是：在长轨迹、异步 rollout、重尾长度分布和 policy lag 的条件下，梯度应如何被计算、修正和应用。它讨论的是更新机制本身，包括同步与异步、单 rollout 与组采样、裁剪与价值建模等问题。

第二层是**协作层**。这一层关心的是：多个 agent 在交互期如何共享上下文、文件、会话状态与任务中间结果。它优化的是 handoff 成本、可见性和交互连续性，典型对象是共享工作区、上下文继承、跨 agent 文件可见性等机制。

第三层是本文要强调的**准入层**。这一层关心的问题并不是“如何更新”，也不是“如何协作”，而是：**当大量轨迹已经被 worker 生成之后，哪些经验应被谁阅读，阅读到什么深度，又在何种条件下才能接触基座策略的参数更新**。这是一个经验数据流的准入语义问题。

本文的基本判断是：在长时程、异步、异质 worker 的场景下，系统的失败模式并不完全来自优化器本身。即使异步训练提高了吞吐，系统仍可能把大量低价值、强噪声、强偏移或高风险轨迹无差别地暴露给基座策略；即使共享上下文改善了协作，系统仍未回答哪些经验只应被观察，哪些经验必须被隔离，哪些经验才有资格进入参数更新。也就是说，**训练稳定性**与**经验准入语义**是相关但不等同的问题。

### 2.2 动机现象

本文并不把单一论文或单一产品当作普适证据，而是从两个现象出发说明这一层为何值得被单独提出。

在训练侧，长时程 agentic RL 已经暴露出同步组采样与异步训练之间的结构性张力。同步组采样方法（如 GRPO [2]）容易在重尾轨迹上产生等待与空转；异步单 rollout 方法虽然缓解吞吐问题，却会强化 off-policy 与 policy lag 的压力。SAO [1] 清楚地展示了优化层上的重要推进：它试图回答“如何在单 rollout 异步条件下把训练继续稳定地跑下去”。但它并不直接回答：异步产生出来的大量轨迹里，哪些应被基座策略真正看见——而这正是本文的坐标：稳定之后，哪些经验值得惊动本体。

在协作侧，共享上下文、多 agent 文件可见性与工作区继承显著降低了交互期协作摩擦。这类系统优化的是“多个 agent 如何一起完成任务”，而不是“这些交互轨迹如何被用于后续基座策略更新”。当我们把交互期协作与训练期经验准入混为一谈时，就会误以为“共享更多”天然意味着“学得更好”。本文认为这是一种层次混淆。

因此，这里的缺口不在于现有工作完全无效，而在于它们大多回答了相邻问题，却没有明确回答一个更尖锐的问题：**轨迹生成之后，什么经验有资格接触 base policy，什么经验只能被观察，什么经验必须先被隔离**。

### 2.3 主张层级

为了避免把诊断、立场与设计偏好混写，本文将自己的内容分成三层主张。

**C1：诊断性主张。**  
在长时程、异步、异质 worker 的 agentic RL 中，`被动全量摄取` 与 `全局共享式暴露` 都会制造结构性张力。前者容易带来噪声淹没、低价值深读与信用分配不透明；后者容易带来上下文压力、冲突延迟以及“所有经验都可见”所导致的边界消失。优化器改良能够缓解其中一部分问题，但不能自动给出“经验应如何被分层接触”的答案。

**C2：架构性主张。**  
应将经验准入控制提升为一个独立的数据流层。一个可能值得检验的组织方式是：用廉价指纹与局部不确定性信号做粗路由，将轨迹送入分层缓冲区，对部分轨迹做选择性深读，并只允许经过多阶段验证的受限子集接触基座策略的低频更新。本文将这一立场称为 `experience routing`。它是一种系统组织假设，而不是训练算法本身。

**C3：设计性主张。**  
指纹宽度、时间窗长度、熵阈值、控制周期、晋升条件以及隔离标签，都只是设计参数。它们不构成本文的核心贡献，也不应被当成结果引用。本文真正想保住的，不是某组数值，而是更上层的判断：**基座策略不应默认面对所有已产生经验，而应只面对一个经过显式准入语义约束的受限子集**。

这三区分非常关键。C1 试图说明“问题存在”；C2 试图说明“值得把它定义成独立对象来检验”；C3 则只是实现表面。若读者最终不同意 C2，也应当是因为对这一架构立场本身有异议，而不是因为某个阈值写得不够好。

## 3. 相关工作、最近邻与残余缺口

本文并不主张自己处于一片空白地带。恰恰相反，经验准入控制之所以容易被忽视，正因为它散落在多个已成熟的研究方向之间。要证明本文值得存在，关键不在于罗列“我们和哪些方向有关”，而在于说明：**为什么这些方向的组合，仍然没有给出清晰的准入语义**。

### 3.1 最近邻一：优先回放与轨迹筛选

与本文最近的方向，是优先回放、轨迹排序和经验筛选。Prioritized Experience Replay 通过 TD-error 改变样本进入 learner 的概率，核心问题是“哪些 transition 更值得被 SGD 看见”。在更广义的后训练实践中，trajectory ranking、data curation 和 sample filtering 也都在做类似事情：不是让所有数据等权，而是对训练样本进行优先级管理。

本文与这些工作的差异不在于“也想筛选数据”，而在于：**本文讨论的不是 batch 采样概率，而是经验的准入语义**。也就是说，问题不只是“哪些样本更重要”，而是“哪些轨迹甚至不应该被完整物化和深读”，“哪些轨迹必须从基座策略更新中被物理隔离”，“哪些异常轨迹虽然不能更新权重，却必须保留分析价值”。优先回放可以成为 warm tier 的排序器，却不足以单独定义 quarantine semantics。这正是本文希望补出的缺口。

### 3.2 最近邻二：异步 actor-learner 与 agentic RL 优化器

IMPALA 及其后续 actor-learner 体系，解决的是 acting 与 learning 解耦后的吞吐与修正问题。更近一步，面向 LLM agent 的异步训练工作则在回答：长时程轨迹、单 rollout 更新与 policy lag 并存时，如何仍然把优化过程跑稳。SAO [1] 正是这条线上与本文主题最近的代表；GRPO [2] 则提供同步组采样基线，用以对照异步设定为何会放大经验暴露问题。

这些工作的重要性毋庸置疑，但它们优化的是**梯度如何在数据到达之后被应用**，而不是**哪些数据有资格接近基座策略**。本文的立场并不是用 routing 替代异步优化器，而是强调二者回答的是不同问题：优化器决定 update rule，准入层决定 update support。一个系统完全可以让 SAO 充当优化器 \( \mathcal{A} \)，同时再加一层路由机制限制哪些轨迹能够进入 \( \mathcal{A} \) 的可见集。若不把这两者分开，系统就容易陷入一种幻觉：只要优化器更稳定，经验暴露问题就会自动消失。

### 3.3 最近邻三：安全过滤、保守更新与 staged review

Safe RL、shielding、constrained update 以及 offline RL 中的保守方法，都触及了一个与本文高度相邻的问题：并非所有经验都应当以同样方式影响策略。Safe RL 往往通过约束或拦截防止危险行为，offline RL 则常通过 loss 层面对分布外动作保持保守。

本文与这些方向的差异在于，本文强调的不是“如何在损失函数里保守”，而是“如何在系统层面规定经验接触 base policy 的边界”。这意味着两个额外要求。第一，异常或危险轨迹不应被简单销毁，因为它们可能仍然具有分析价值；第二，经验是否可用于更新，和经验是否值得保留分析，是两个不同维度。换言之，本文要引入的是**准入语义与隔离语义同时存在**的系统层，而不只是一个危险样本过滤器。

### 3.4 次近邻：层级 RL、好奇心、蒸馏与协作记忆

层级 RL 通过上层—下层结构在动作空间上做时间抽象；本文则试图在经验数据流上做分层。两者都使用“层级”语言，但工作平面不同。好奇心与不确定性方法把熵、预测误差或新颖性转成内在奖励，主要服务于探索激励；本文若使用不确定性信号，也只是把它当作调度特征，而不是奖励本身。蒸馏通常讨论能力从 teacher 到 student 的迁移；本文中的 tour agent 更接近一个只读 gate，用于决定哪些轨迹需要升级处理，而不是能力传递本身。

至于多 agent 共享工作区、长期记忆和协作式上下文系统，它们与本文的关系更应被谨慎处理。它们能说明“共享一切”是一种真实存在的系统冲动，但不能直接作为训练准入层的证据。交互期文件共享，不等于训练期经验准入。把二者直接等同，会导致类别错误。

### 3.5 残余缺口

综合上述方向，可以更精确地陈述本文想占据的位置：

现有工作已经分别回答了以下问题：  
如何优先采样样本；  
如何在异步环境下稳定更新；  
如何对危险行为施加约束；  
如何让多个 agent 在交互期共享上下文；  
如何用数据筛选改善后训练。

但对于昂贵、长时程、异质、可能带有安全外溢的 LLM-agent 轨迹，我们仍缺少一个明确的系统抽象来回答：

- 哪些轨迹只值得被廉价信号粗看，而不值得完整深读；
- 哪些轨迹不能进入参数更新，却必须被隔离保留；
- 哪些轨迹可以在多阶段验证后进入基座策略的低频更新；
- 以及，这一切如何作为一个**独立于优化器、但可叠加于优化器之上的数据层**被表达。

本文将这一缺口命名为**经验准入控制**。如果这一命名最终站不住，最可能的理由应当是：已有的 replay、filtering 和 safe update 术语已经足够表达这些语义；而不应只是因为某个阈值写得不够好。也正因此，本文后续的形式化与可证伪协议，服务的不是某套固定参数，而是这个更根本的问题：**经验如何以受限、分层、隔离的方式接触基座策略**。

### 3.6 最小不可约语义：为何不只是“换名的 PER / filtering”

若批评者问：去掉花哨名称后还剩什么？本文回答必须落到**PER、普通 sample filtering、shield 删除式过滤所不强制具备**、而准入层若要成其为独立对象则**不可拿掉**的原语。下列四条同时成立时，才值得使用“经验准入控制”这一名称；任一长期缺失，命名应撤回，改回既有术语即可。

| 不可约原语 | 含义 | PER / 优先级采样通常有？ | 删除式 safety filter 通常有？ |
|------------|------|---------------------------|--------------------------------|
| **P1 默认无深读权** | 轨迹默认不进入完整物化与高成本深读；深读是稀缺许可，不是默认权利 | 否（假设 transition 已在 buffer、讨论的是采样权重） | 否（常在已物化轨迹上判决） |
| **P2 隔离 ≠ 删除** | 高偏移 / 高风险轨迹可禁止进入 \(D_{\mathrm{adm}}\)，但必须可保留为分析对象 | 否 | 通常否（倾向拦截或丢弃） |
| **P3 深读 ≠ 准入** | warm 可被展开与巡游处理，本身不构成对 \(\theta\) 的更新资格 | 否（被采样即进入学习） | 部分相关，但不区分观察与更新 |
| **P4 可见集真包含** | 制度性约束 \(D_{\mathrm{adm}} \subsetneq D_{\mathrm{all}}\)（至少在含 hot 的运行中严格成立），而非“全量可学、仅重加权” | 否（重加权仍面向已入池全体） | 否（通常收缩动作，不定义训练可见集制度） |

因此：PER 可以担任 warm 区内的排序器；shield 可以提供 hazard 检测信号；**它们都不自动给出 P1–P4 这套接触制度**。若某系统实现了 P1–P4 却坚持叫 replay，那是术语选择；若某系统只做 TD-error 重加权却自称经验准入控制，则是命名膨胀。本文的 novelty 压力全部落在 P1–P4，而非任何具体指纹公式。

## 4. 最小形式化草图

本文不试图在此给出一个完整算法，而是希望为“经验准入控制”建立一个最小可讨论对象。这里的形式化不是为了增加技术外观，而是为了明确：**如果经验准入控制是一个独立系统层，它至少应当接收什么、输出什么、约束什么**。

### 4.1 对象与位置

设一组 workers \( \{w_i\} \) 在环境中生成轨迹
\[
\tau = (o_t, a_t, r_t)_{t=1}^{L},
\]
其中 \(o_t\) 为观测，\(a_t\) 为动作，\(r_t\) 为外部反馈。设基座策略为 \( \pi_\theta \)，优化器为 \( \mathcal{A} \)。优化器接收一个经验集合并对 \( \theta \) 进行更新；它可以是 GRPO 类方法、单 rollout 异步优化器，或其他 actor-learner 变体。本文不限制 \( \mathcal{A} \) 的具体形式。

我们讨论的经验准入控制层，位于 worker rollout 与优化器之间。它不定义环境，不替代优化器，也不直接规定 loss。它要回答的是另一件事：**什么样的经验可以接近 \( \mathcal{A} \) 的可见集，什么样的经验只能被观察，什么样的经验必须被隔离**。

因此，本文把整个数据流抽象为：
\[
\tau \xrightarrow{\phi} x \xrightarrow{r} \mathcal{B} \xrightarrow{g} D_{\mathrm{adm}} \xrightarrow{\mathcal{A}} \theta,
\]
其中 \( \phi \) 是廉价特征映射，\( r \) 是路由函数，\( \mathcal{B} \) 是分层缓冲结构，\( g \) 表示可选的中间判别或升级机制，\(D_{\mathrm{adm}}\) 是最终允许优化器接触的经验集合。

### 4.2 强形式假设

本文讨论的是经验准入控制的强形式，因此需要一个白盒假设：worker 在生成轨迹时，系统至少可以获得以下信息之一：

1. 中间隐藏表示 \(h_t\)；
2. 局部动作分布 \( \pi_t(\cdot \mid o_t) \)；
3. 可从内部推导出的不确定性或变化信号。

若系统只能访问最终文本输出或工具调用日志，那么仍可构造退化的文本路由器，但那会把问题弱化成另一类后验筛选机制。本文主张的对象，依赖的是**在轨迹尚未被完整深读之前，就能提取局部代理信号**。

### 4.3 经验指纹

经验准入控制层的第一原则是：不能默认完整物化所有轨迹。否则它只是换名后的被动经验池。因此，它需要依赖一组廉价、流式、局部的代理信号，对轨迹做第一轮判断。

在长度为 \(k\) 的时间窗上，定义一个局部经验指纹：
\[
x_t = \phi(\tau_{t-k+1:t}) = (s_t, u_t, \delta_t),
\]
其中：

- \(s_t\) 表示轨迹窗口的低维 sketch 或指纹；
- \(u_t\) 表示不确定性信号，例如归一化熵；
- \(\delta_t\) 表示局部决策变化幅度，例如相邻策略分布之间的散度。

本文不主张某一具体实现是标准答案。重要的不是是否使用随机投影、某种固定散度，或某个固定窗长，而是这些量满足一个功能性条件：**它们足够廉价，以至于系统可以在不完整展开轨迹的前提下，对经验做第一轮准入判断**。

因此，这里的形式化重心不是某个数值设定，而是下面这个抽象：
\[
\phi : \tau_{t-k+1:t} \mapsto x_t,
\]
即：把原始轨迹的局部动态压缩成可供准入层读取的代理表征。

### 4.4 路由与缓冲语义

在得到局部指纹之后，系统应用一个路由函数
\[
r(x_t) \in \{\mathrm{archive},\ \mathrm{warm},\ \mathrm{hot}\}.
\]

这三类输出不是简单的优先级高低，而是三种不同的**接触语义**：

- `archive`：轨迹不值得进一步深读，只保留廉价记录或摘要；
- `warm`：轨迹值得继续观察，可被选择性展开，交由更高成本的中间模块处理；
- `hot`：轨迹表现出高偏移、高异常或高风险，必须从基座策略更新中隔离，但不得直接销毁。

这一定义与普通的 sample ranking 有本质差异。排序只回答“哪个更重要”；而这里的路由还回答“哪个可以深读”“哪个可以被观察”“哪个绝不能接触基座更新”。因此，经验准入控制的核心不只是优先级，而是**经验与基座策略之间的边界关系**。

### 4.5 延迟标签与异常语义

对进入 `hot` 的轨迹，系统还可以在更晚时刻赋予更细标签：
\[
\ell(\tau) \in \{\texttt{promising},\ \texttt{hazard}\}.
\]

这里的关键是，标签判定往往晚于隔离动作。也就是说，系统并不需要在轨迹生成的瞬间就知道它是“高价值异常”还是“危险异常”；系统首先要做的是**把它从基座更新路径中隔离出来**，然后等待终局回报、安全监测器或离线分析结果到齐，再决定其后续命运。

这一步非常重要，因为它把两个经常被混淆的问题分开了：

- 一个样本是否能用于更新；
- 一个样本是否值得保留分析。

在本文看来，前者是准入问题，后者是知识保留问题。经验准入控制层必须同时处理二者，而不能把“高风险”直接等同于“无价值”。

### 4.6 基座可见集

设 \(D_{\mathrm{all}}\) 为系统拥有的全部经验，\(D_{\mathrm{adm}}\) 为优化器可见的经验集合。本文的核心约束是：
\[
D_{\mathrm{adm}} \subseteq D_{\mathrm{restricted}} \subseteq D_{\mathrm{all}},
\]
其中 \(D_{\mathrm{restricted}}\) 表示经过额外验证后被允许接近基座策略的受限子集。

这一定义表达的不是某个实现细节，而是本文最重要的制度性主张：**基座策略的更新支持集不应默认等于系统拥有的全部经验**。在长时程、异质、多 worker 的 setting 中，默认开放所有经验接触基座，本身就是一种未经辩护的系统选择。

因此，本文要求至少满足以下硬约束：

1. `hot-hazard` 轨迹不得直接进入 \(D_{\mathrm{adm}}\)；
2. `warm` 轨迹可以被深读，但深读本身不构成准入；
3. 从 `warm` 或 `hot` 进入 \(D_{\mathrm{restricted}}\) 必须经过独立于初始路由的额外验证；
4. 优化器 \( \mathcal{A} \) 对 \( \theta \) 的更新只允许基于 \(D_{\mathrm{adm}}\) 发生。

换言之，经验准入控制层真正要制度化的，是**谁有资格影响 base policy**。

### 4.7 巡游代理

为了避免把所有“是否值得惊动本体”的判断都推回 \( \pi_\theta \)，系统可以引入一个只读或读多写少的中间模块，记作 \(g_\phi\)。它的作用不是替代基座策略，而是在廉价指纹与直接惊动基座之间，提供一个受限但更细的判断层。

可形式化为：
\[
z = g_\phi(\tau_{\mathrm{partial}}),
\]
其中 \(z\) 为摘要、升级建议或风险提示，\(\tau_{\mathrm{partial}}\) 为局部展开后的子轨迹。关键在于：\(g_\phi\) 的输出本身不应直接构成基座更新依据，而只能作为晋升、回退或继续观察的中间证据。

因此，巡游代理的本质不是第二个本体，而是一个带预算约束的 gate。它之所以有意义，不是因为它更聪明，而是因为系统通常需要一层介于“廉价粗路由”与“直接接触 base policy”之间的中间判断结构。

### 4.8 本节小结

到此为止，本文为经验准入控制建立了一个最小接口层。它至少包括：

- 一个廉价特征映射 \( \phi \)；
- 一个路由函数 \( r \)；
- 一组带隔离语义的缓冲区 \( \mathcal{B} \)；
- 一个受约束的基座可见集 \(D_{\mathrm{adm}}\)；
- 以及一个可选的中间判别器 \(g_\phi\)。

这一形式化并不等于某个具体算法。它的作用只是把本文的中心命题落到可讨论的接口层上：**优化器决定如何学习，而准入层决定允许什么经验被学习所看见**。

## 5. 架构立场与机制判断

在明确最小形式化对象之后，本文接下来给出的不是系统蓝图，而是一组更高层的机制判断。它们服务于本文的 C2：如果经验准入控制值得被看作一个独立系统层，那么它在组织原则上至少应倾向什么，而不应默认什么。

### 5.1 主动巡游，而非被动全量池

本文的第一项立场是：在长时程、昂贵、异质性强的 LLM-agent 轨迹上，**被动全量摄取不应再被视为默认合理的经验组织方式**。

被动经验池有一个通常未被明说的前提：所有已生成轨迹都值得以某种方式被 learner 深度接触。在短链条、低成本、近同分布环境里，这种前提也许还可接受；但在 agentic RL 中，它会同时造成三种问题。其一，系统会在海量平庸轨迹上浪费深读预算。其二，长轨迹使得局部关键决策与终局回报之间的因果关系变得稀薄。其三，高偏移、高风险经验若没有明确的隔离语义，就会在“先收进来再说”的逻辑下过早接近基座策略。

因此，本文偏好一种更主动的结构：先用廉价代理信号粗看，再决定哪些经验值得付出完整展开和深读的代价。这里的核心不是“更聪明地采样”，而是**不再默认深读权属于所有轨迹**。

### 5.2 灰度缓冲，而非二元过滤

第二项立场是：经验准入控制不应采用简单的“可用 / 不可用”二元过滤，而应引入灰度缓冲结构。

原因在于，系统面对的经验远不止“好样本”和“坏样本”两类。至少还存在一类处于中间地带的经验：它们偏移、陌生、具有观察价值，但尚不能被定性；另一些经验则明显异常甚至高风险，必须被隔离，但又不能直接删除。如果系统没有灰度地带，就会在两种错误之间摇摆：要么过早扼杀探索，要么过早暴露本体。

因此，`warm` 和 `hot` 的意义不是简单的等级差异，而是接触语义差异：

- `warm` 表示可观察、可深读，但不自动获得更新资格；
- `hot` 表示必须隔离于基座更新之外，但保留分析与后续判定资格。

灰度缓冲真正解决的，不是排序问题，而是**中间状态的合法性问题**。它为“尚未可用，但不能丢弃”的经验提供了制度位置。

### 5.3 异常样本应被隔离利用，而不是直接清除

第三项立场是：系统不应把异常样本简单理解为污染物，而应把它们视为边界信息。

一类异常样本主要揭示风险，它们提示系统正在靠近安全红线、奖励漏洞或策略漂移。这类样本不能进入参数更新，但应被用于外围判别器强化、reward model 审查或环境漏洞定位。另一类异常样本则可能同时具有高偏移与高价值潜力；它们当前同样不应接触基座权重，但应被保留为后续深读、聚类或分析的对象。

这一判断的关键在于，把“是否可用于更新”与“是否值得保留”彻底拆开。许多经验筛选框架默认危险样本的最佳命运是删除；而本文更强调：在 agentic RL 中，异常经验首先是系统边界的证据。过早删除它们，等于主动丢弃关于系统失稳机制的知识。

因此，本文倾向的不是一个更强硬的 shield，而是一种更有记忆性的 quarantine。系统需要的不是更快地忘掉异常，而是更慢地让异常靠近基座。

### 5.4 基座策略应低频、受限地接触经验

第四项立场是：基座策略不应作为所有经验处理的第一响应者，而应当是一个低频、受限、最后接触经验的组件。

在大规模 agentic RL 中，最昂贵也最脆弱的对象，恰恰是承担最终先验的 base policy。如果它默认面对所有已生成经验，系统就会把最大的噪声和偏移集中暴露给最核心的权重。本文因此偏好一种职责分离结构：让 workers 承担绝大部分试错成本，让廉价路由承担第一轮筛分，让中间判别器承接更高成本但仍受限的判断，而让 base policy 仅在经验经过多阶段过滤之后，才以较低频率接触受限更新集。

这里“低频”不是目的本身，它只是另一项更重要制度安排的结果：**基座接触经验的门槛必须被显式规定，而不是由系统默认开放**。

### 5.5 巡游代理不是第二个本体

第五项立场是：若系统引入中间判别层，它不应演化为第二个基座策略。否则，所谓准入控制只是在复制一个更小、但同样昂贵的 learner，而没有真正回答“谁应该先看”的问题。

因此，巡游代理的设计原则应当是：

- 视野受限；
- 输出受限；
- 升级权限明确；
- 对基座负责，但不替代基座。

它可以比廉价指纹更强，但必须比 base policy 更窄；它可以判断“这段经验值得进一步处理”，但不应承担“替本体学习”的职责。它存在的意义，不在于复制能力，而在于提供一个预算受限的中间 gate。

### 5.6 这些是机制判断，不是参数结果

最后必须再次强调，上述内容都是架构立场，而不是经验结果。本文并不要求某个固定指纹维度、某个固定窗长、某个固定阈值，才能让这些判断成立。真正值得被检验的，不是 `128` 是否优于 `256`，也不是 `0.7` 是否优于 `0.6`，而是以下更高层的问题：

- 主动巡游是否优于被动全量池；
- 灰度缓冲是否优于简单二元过滤；
- 异常样本的隔离利用是否优于直接删除；
- 基座策略的低频受限更新是否优于默认开放。

如果这些原则不成立，那么本文的立场就应被放弃；如果这些原则成立，参数才值得进入校准阶段。

### 5.7 本节小结

因此，本节真正要保住的，不是某套机制细节，而是一组制度性判断。它们共同指向同一个核心结论：

**经验准入控制的关键，不是找到一个最优评分器，而是建立一套关于接触顺序、隔离边界和基座可见性的明确制度安排。**

## 6. 证据政策与论证边界

本文是一篇立场文，而不是方法论文或系统实证报告。因此，本文的说服力不应建立在未经测量的数字、未经复现的案例，或对设计参数的强行外推之上。为了避免把系统直觉误写成经验事实，本文在证据层面采用一套更严格的约束。

### 6.1 本文能主张什么，不能主张什么

本文可以主张三类内容。

第一类是**概念层面的区分**。如果一个问题长期散落在多个局部术语之中，而这些术语又未能给出足够清晰的系统表达，那么将其重新提升为独立对象，本身就是一种有效贡献。本文关于“经验准入控制”的主张首先属于这一类。它的成立不依赖某组具体参数成立，而依赖于下述判断是否成立：在 agentic RL 中，`什么经验有资格接触基座策略` 确实构成一个独立于优化器设计与协作界面的系统问题。

第二类是**架构层面的判断**。例如，是否应默认所有轨迹都可被深读，是否应为异常经验保留隔离语义，是否应将基座更新限制在一个受控的经验子集之上。这些判断可以基于系统分析、结构张力与跨文献比较来提出，但它们仍属于待检验的假说，而不是已经被数据证明的结论。

第三类是**可证伪条件的规定**。一篇立场文若要具备研究价值，至少应说明：在什么情形下，它所提出的对象或组织原则应被放弃。本文第 7 节的作用就在于此。

与此相对，本文**不能**：把指纹阈值等写成最佳设定；把单篇训练曲线的崩溃步数写成普适规律；把附录中的玩具执行记录外推为大规模 LLM 收益；把冻结 API rollout 写成「微调了基座」。

换言之，价值首先来自**问题对象与论证纪律**；附录不参与“是否打穿靶心”的判定。

### 6.2 如何使用已有文献

本文需要已有文献来支撑背景张力，但不应误用它们来替代直接证据。因此，本文对已有文献的使用遵循以下原则。

首先，关于训练不稳定、异步优化和长时程轨迹问题的引用，只能被用来说明：优化层上的 tension 是真实存在的，且当前研究正在积极应对。它们不能自动推出本文的准入层主张成立。也就是说，`优化器存在问题` 不等于 `经验准入控制必然正确`。

其次，关于共享工作区、多 agent 协作和上下文继承的现象，只能被用来说明：系统设计上确实存在一种“让更多经验彼此可见”的冲动。它们同样不能直接充当训练论证。交互期的可见性，不等于训练期的可更新性。若把二者直接等同，文章就会犯类别错误。

再次，关于 replay、offline RL、safe RL、distillation、curiosity 等相关方向的引用，只能用于界定最近邻和残余缺口，而不能通过“相关工作很多”来反向制造本文的新意。本文真正需要做的，不是证明自己和很多方向都有关，而是证明这些方向的组合仍未给出清晰的准入语义。

### 6.3 数字的地位

本文允许出现设计性数字，但这些数字只能扮演**占位符**的角色，而不是结论。它们的作用仅限于两个方面。

其一，用于说明问题的可操作性。没有任何量化占位，文章会停留在纯概念层面，难以进入可检验状态。适度的参数占位，例如“窗长”“控制周期”“受限更新频率”，有助于说明这不是纯粹修辞。

其二，用于帮助构造 falsification protocol。若没有最小指标、最小失败条件和最小比较对象，立场文就会滑向不可证伪。

第三类数字是**附录 C 中的执行记录**（深读比、成功率等）。它们不得进入摘要或结论的“有效性”句式；主文至多声明“存在可运行实例”。

占位数字（阈值、窗长）仍不得承担结果功能。

### 6.4 本节的作用

论证纪律压缩为三档强度：**强**主张问题对象应被命名；**中**主张架构假说值得检验；**弱**主张设计参数方向。附录执行记录不构成第四档“已验证有效”。越级叙述即违规。

## 7. 最小可证伪协议

如果经验准入控制要从“一个看起来合理的 framing”变成“一个值得继续投入的研究对象”，它至少必须经受最小反驳测试。本文因此不把实验设计写成附会性的 future work，而把它作为立场本身的一部分。换言之，**若本文无法说明自己该怎样被否掉，那么它还不配被当作研究立场讨论**。

### 7.1 比较目标

最小对照的目的，不是证明本文架构优于所有可能替代方案，而是回答一个更有限但更关键的问题：在保持优化器、环境和 worker 策略类不变的前提下，**把经验准入控制显式提升为一层数据流组织机制，是否比被动经验池更值得继续研究**。

因此，最小对照至少应包含两个 arms：

| Arm | 数据流组织 |
|-----|------------|
| A | 被动经验池：轨迹近乎全量可被 learner 深读或进入 replay |
| B | 准入控制：廉价指纹路由 + 灰度缓冲 + 选择性深读 + 受限更新集 |

两组实验必须共享同一环境分布、同一 worker 策略类、同一优化器 \( \mathcal{A} \) 与相同的计算预算口径。也就是说，比较对象不应是“更好的优化器 vs 更差的优化器”，而应是**同一优化器之上的两种经验组织方式**。

### 7.2 核心指标

本文认为，最小评估不应只看任务回报，而应至少同时观察四类指标。

第一类是**深读负担**。如果经验准入控制成立，它至少应减少被完整展开、被高成本模块处理、或被 learner 直接接触的深读量。一个可操作指标是有效深读比，即高成本处理 token 数与总轨迹 token 数之比。若这项指标与被动经验池无显著差异，那么“准入”就很可能只是多加了一层系统复杂性。

第二类是**训练效率或资源压力**。在异步 setting 中，可以考察 idle accelerator fraction、墙钟时间、或单位有效更新的资源消耗。经验准入控制不必保证绝对节省，但若加上巡游代理、缓冲与额外判别后，端到端代价没有任何改善，它的工程动机就会显著削弱。

第三类是**任务表现**。包括固定评测集上的平均回报、成功率、鲁棒性或泛化表现。本文并不要求准入控制必须在所有设定下显著超越被动经验池，但至少不能在减少深读负担的同时系统性破坏主任务表现。

第四类是**安全与隔离指标**。这是本文与一般 replay 改进不同的关键之处。系统必须能够统计危险轨迹是否穿透隔离边界、是否有 `hot-hazard` 经验进入基座更新、以及隔离区是否确实保留了异常样本供后续分析使用。若没有这一组指标，本文所谓 quarantine semantics 就无法被检验。

### 7.3 预注册失败条件

为了避免“只要某项局部指标有点改善就算成功”的叙事偏差，本文要求在实验前就写明失败条件。以下任一情况发生，都应视为在该设定下拒绝本文立场的充分理由。

**失败条件 1：灰度层失效。**  
若 `warm` 区长期吸收了绝大部分经验质量，既未起到过滤作用，又未形成明确的后续分流，那么灰度缓冲就退化成了另一种被动池。换言之，如果大多数轨迹只是被换个名字留在中间层，本文主张的准入语义就没有真正建立起来。

**失败条件 2：额外机制没有换来任何预算改善。**  
若引入路由器、巡游代理和额外缓冲之后，深读负担、墙钟效率或资源利用没有出现有意义的改善，那么经验准入控制就可能只是把复杂性转移到了另一个模块，而没有改变系统的总体经济性。

**失败条件 3：受限更新集引入持续性性能回撤。**  
若从 `warm` 或 `hot` 晋升进入受限更新集的经验，在多次评测中持续引发基座表现回撤，则说明准入机制未能起到“稳定吸收”的作用，反而在更隐蔽的位置把异常经验带入了核心权重。

**失败条件 4：危险经验穿透隔离边界。**  
若 `hot-hazard` 类型轨迹以任何形式进入 \(D_{\mathrm{adm}}\) 并参与基座更新，则本文最重要的制度性主张之一直接失效。因为一旦这一条不能被保证，所谓 quarantine 就只剩叙事，不再是系统事实。

**失败条件 5：路由代理信号与深读后学习增益的秩相关不显著（强形式判负）。**  
在固定任务与固定 \(\mathcal{A}\) 下，若路由所用代理信号（如熵、局部散度、指纹距离）经校准后，与 held-out 上“深读该窗是否改善学习”的标签之秩相关持续不显著（或路由策略相对随机归档无增益），则**强形式经验准入控制在该任务上判负**。此时不应再通过更换阈值叙事续命；至多退化为纯后验文本筛选（弱形式），并不得与强形式混称。

上述条件中，第 4、5 条为硬失败；第 1–3 条共同决定该立场在具体设定下是否值得继续投入。

### 7.4 弱成功标准

作为一篇立场文，本文并不需要在一开始就定义“强成功”。更现实的做法是规定一个弱成功标准：如果满足以下条件，则可以认为经验准入控制至少值得进入更大规模实验。

- 相比被动经验池，深读负担出现明确下降；
- 主任务表现没有明显恶化；
- 预注册失败条件未被触发；
- 异常隔离区确实保留了后续可分析样本，而不是纯粹的垃圾堆积。

这一定义刻意是保守的。因为本文此刻要争取的，不是“已经证明自己正确”，而是“已经证明自己值得被更严肃地检验”。

### 7.5 为什么 falsification 比 ablation 更重要

很多系统稿都会附一个 ablation plan，但本文强调的不是“以后可以做消融”，而是**经验准入控制如果要成立，必须先接受被否掉的条件**。这是因为本文的对象不是一个具体超参数技巧，而是一个研究对象本身。如果它没有明确的失败标准，它就会退化成一种永远可以事后解释的架构偏好。

因此，第 7 节并不是附录式的实验展望，而是全文论证的一部分：经验准入控制之所以值得被单独命名，前提之一就是它能被单独反驳。

### 7.6 附录指针

§7.1–7.5 已定义协议与预注册失败条件。若需查阅可运行代码路径与玩具尺度执行记录，见**附录 C**（非主结论，不参与主文论证闭环）。主文到此结束于：“协议可被单独反驳”。

## 8. 局限性与反对意见

一篇立场文若要有学术价值，不能只把自己最顺的论证写出来，还必须主动展开最强的反对意见。本文至少面对以下七类实质性挑战。若这些挑战不能被认真回应，那么“经验准入控制”很可能仍只是一个过度包装的工程直觉。

### 8.1 反对意见一：这不过是 replay/filtering 的重新命名

这是最重要、也最危险的质疑。批评者完全可以说：本文所谓经验准入控制，不过是优先回放、样本筛选、安全过滤和 staged update 的重新组织；换句话说，作者只是把已有经验工程改了个更大的名字。

这是一个必须认真对待的挑战。本文的回应不是否认相似性，而是把差异压到 **§3.6 的 P1–P4**：默认无深读权、隔离≠删除、深读≠准入、\(D_{\mathrm{adm}}\subsetneq D_{\mathrm{all}}\)。已有方法大多在 sampling、loss 或约束层规定“如何使用数据”，而不强制这四条接触制度同时成立。如果读者认为 P1–P4 仍可被既有术语完全吸收，则命名应撤回——这是合法否决，不是参数之争。

需要诚实补一句：即便 P1–P4 在语义上不可约，本文也**尚未**给出“哪一条或哪几条原语驱动了相对 PER 的行为差异”的因果分解；聚合对照不能替代逐条机制验证（见第 9 节）。

### 8.2 反对意见二：廉价信号未必与可学习价值相关

经验准入控制的第一轮判断依赖廉价代理信号，而这一步天然面临一个风险：不确定性高、变化大或局部异常，并不自动意味着“对学习有价值”。如果这些信号与真实可学习结构之间相关性很弱，那么系统就可能把真正值得保留的轨迹归档掉，把无意义噪声留在观察区。

这不是局部实现问题，而是本文强形式最深的统计脆弱性之一。缓解只能是方法论层面的：将廉价信号视作特征而非结论；允许路由器被学习或校准。若相关性建立不起来，应按 **§7.3 失败条件 5** 直接判负强形式，而不是用“再调阈值”无限延期。

### 8.3 反对意见三：隔离先于定性会显著增加系统复杂度

本文主张“先隔离、后定性”，这在逻辑上干净，但在工程上代价明显。系统必须为尚未被判断的异常样本预留存储、缓冲、标签延迟和离线分析流程。批评者完全可以说：相比直接丢弃，本文只是把风险从模型里挪到了系统复杂性里。

这个批评是成立的。本文并不否认准入层会增加系统复杂度；相反，它的立场正是：在 agentic RL 的长时程与高风险场景中，**把复杂度显式化、制度化，比把它隐含地压进 base policy 更可取**。但这仍然只是一个架构判断，而不是先验真理。若系统复杂性远超收益，第 7 节已经规定应当拒绝这一立场。

### 8.4 反对意见四：白盒假设过强

本文的强形式依赖隐藏状态、策略分布或局部不确定性信号，而现实中大量 agent 系统运行在闭源 API 或受限 SDK 之上。这意味着本文最有力的形式，可能只适用于自部署或深度可观测的系统，而不适用于大量商业 agent 场景。

这是一个实质限制，而不是实现细节。若系统只能访问最终文本和工具日志，那么经验准入控制会退化成更弱的文本后验筛选。本文不应把这种弱形式与强形式混为一谈。更严苛地说，白盒假设如果不能被满足，本文的主张就只能作为一个较窄的研究对象成立，而不能被泛化到所有 agentic RL。

### 8.5 反对意见五：协作层与准入层的类比可能是误导性的

本文从协作工作区、共享上下文等现象获得了动机，但批评者可能指出：交互期上下文共享与训练期经验准入之间并没有严格同构关系，把前者作为后者的启发容易导致类比过度。

这类批评是合理的。因此，本文必须坚持一个边界：协作层现象只能作为系统直觉来源，而不能作为直接证据。若读者发现全文仍在用协作层类比替代训练层论证，那说明这篇文章还没有真正完成从 popular framing 到 academic position 的跃迁。

### 8.6 反对意见六：没有理论，也没有（够硬的）实验，凭什么单独成文

这是最严厉的问题。Position / preprint 不自动豁免。

主文可辩护的只有两层：第一，P1–P4 给出不可约对象，避免纯换名；第二，预注册失败条件使立场可被单独否掉。附录 C 的玩具执行记录**不构成第三层辩护**，只供复现查阅。若读者要求 LLM 级主结果或 P1–P4 的因果消融，正确回应是承认缺口（第 9 节），而不是把附录数字吹进主结论。

### 8.7 反对意见七：即便问题成立，也未必值得优先解决

最后还有一种更冷静的批评：即便经验准入控制是一个真实问题，它也未必是当前 agentic RL 最紧迫的问题。与优化器稳定性、奖励建模质量、环境设计、工具可靠性相比，准入层是否值得优先投入，本身仍是开放问题。

本文对此不试图给出绝对回答。它的主张更弱，也更具体：在那些轨迹昂贵、长度很长、worker 异质性高、且异常样本具有分析价值的 setting 中，经验准入控制值得被从现有讨论中抽离出来，作为一个独立系统层来检验。它不必在所有任务中优先，但应在适当任务中被单独看见。

### 8.8 本节小结

本节的作用，不是替全文消解所有质疑，而是把最危险的反对意见主动摆出来。因为如果这些问题只能等读者来提，说明这篇立场文的成熟度还不够。相反，只有当本文先承认自己的边界，再说明自己为何仍值得被检验，它才可能从“概念整理”接近“研究立场”。

## 9. 未来工作

作为立场文，本文到此可以结束：对象已命名，否决条件已写清。若后续要从“可检验问题”走向“可操作方法”，至少应补三类工作，且不应与本文体裁混称。

**（1）P1–P4 的因果分解。** 需要研究：在相对被动池 / PER / 删除式 filtering 的对照中，观察到的差异由哪一条或哪几条原语驱动——例如隔离是否降低污染、深读≠准入是否改变更新支持集、还是廉价排序器碰巧优于 TD-error。聚合的 B≻PER 不能回答这一问题；需要针对原语的消融或介入设计。

**（2）开源可更新模型上的可复现主结果。** 在 3B–7B 级开源权重上，用同一 \(\mathcal{A}\) 比较准入与 PER/filtering，多 seed，任务超出玩具 MDP。

**（3）路由器校准。** 将失败条件 5 中的代理信号从手调阈值推进为可学习/可校准对象，并报告与深读后学习增益的秩相关。

## 结论

大语言模型智能体强化学习的进展，主要分布在优化器与协作界面两条线上。本文主张其间还有一层：**经验准入控制（experience admission）**——轨迹生成后谁可读、读多深、何时可碰 \(\theta\)。

本文不声称 C2 已在大规模 LLM 上成立。作为立场预印本，它主张两件事已够清楚、值得公开讨论：（1）准入语义可用 P1–P4 与既有 PER/filtering 区分；（2）该对象可在**预注册失败条件**下被单独否掉。大模型级实证与 P1–P4 因果分解属于第 9 节，不在本文交付范围内。

因此，本文争取的不是「已经证明正确」，而是公开一个可检验、可否掉的问题：**经验是否应当以分层、隔离、低频的方式抵达基座策略。**

## Product Spec: AI 面试助手 (V1.0)

### 1. 产品概述

本产品旨在为招聘 SaaS 平台增加一个 AI 驱动的面试辅助功能。该功能通过实时转录面试对话，自动提取关键信息，并生成结构化的面试评价与报告，从而提升面试效率、标准化评价流程，并减少面试官记录负担。核心价值在于“降本增效”与“标准客观”。

### 2. 目标用户

-   **主要用户：** 用人部门面试官（技术负责人、业务主管等）。他们最关心候选人能力与岗位匹配度，是报告的主要生成者和使用者。
-   **次要用户：** 招聘 HR。他们负责面试流程管理、候选人档案维护，需要快速浏览和归档报告。

### 3. 核心功能（含风险标注和替代方案）

#### 功能一：实时语音转写与录音

-   **描述：** 面试开始时，面试官在 SaaS 平台内一键开启录音。系统实时进行语音识别（ASR），将面试对话转为文字，并同步显示在面试官操作界面上。
-   **模糊点/前提假设：**
    -   假设面试环境网络良好，且背景噪音可控。
    -   假设面试官会主动点击“开始/结束录音”按钮。
    -   假设候选人同意被录音（隐私合规问题）。
-   **风险：**
    -   **高：** 多人同时说话、口音、专业术语、中英文混杂导致转写准确率下降。
    -   **中：** 线上会议场景下，音频流获取的稳定性和延迟问题。
-   **替代方案：**
    -   对于口音/术语问题：提供“关键词/术语库”功能，面试官可预置行业术语，提升识别率。
    -   对于线上会议：优先与腾讯会议、飞书等提供官方 API 的主流平台集成，获取高质量音频流。对于无 API 或兼容性差的平台，提供“系统音频录制”或“麦克风录制”选项（需用户手动配置）。
-   **范围裁剪建议：** **V1 核心功能**。初期仅支持单一声道（面试官+候选人混合），V2 可考虑通过声纹或说话人分离技术实现角色区分。

#### 功能二：关键回答自动提取与重点标记

-   **描述：**
    1.  **自动提取：** AI 根据预设的面试大纲或岗位要求，自动识别并高亮显示候选人在“项目经验”、“技术栈”、“离职原因”等关键问题上的回答。
    2.  **手动标记：** 面试官在实时转写文字上，通过点击“标记”按钮或快捷键，随时标记自己认为重要的片段。
-   **模糊点/前提假设：**
    -   假设系统需要预先知道面试岗位的 JD 或预设问题列表，才能进行针对性提取。否则提取将变得泛化，失去针对性。
    -   “关键回答”的标准是什么？是时间长度、关键词密度，还是与预设问题的语义相似度？
-   **风险：**
    -   **高：** 自动提取不准确，漏掉关键信息或提取了无关信息（即“幻觉”），直接导致面试官不信任。
    -   **中：** 手动标记操作在紧张面试中会增加认知负担。
-   **替代方案：**
    -   **对抗“幻觉”：** 不采用“自动提取”，而是采用“智能摘要 + 高亮关键词”。AI 不主动提取“回答”，而是生成一段面试摘要，并高亮其中与岗位 JD 匹配度高的关键词（如“Python”、“项目管理”、“团队协作”）。面试官手动标记作为补充。
    -   **降低操作负担：** 提供“一键标记”按钮，并支持面试后对转录文本进行二次标记和编辑。
-   **范围裁剪建议：** **V1 核心功能**，但采用“智能摘要 + 关键词高亮”方案替代“自动提取回答”。手动标记功能保留。V2 再基于大量标注数据训练更精准的回答提取模型。

#### 功能三：生成面试评价表（打分）

-   **描述：** 面试结束后，AI 根据转录内容和摘要，自动生成包含“沟通能力”、“技术能力”、“综合素质”等维度的评分表（例如 1-5 分），并给出评语。
-   **模糊点/前提假设：**
    -   假设评分维度和标准是固定的。但不同岗位、不同面试官对“技术能力”的定义不同。
    -   “准确、无幻觉”的要求在此功能上达到顶峰。HR 对 AI 打分非常敏感。
-   **风险：**
    -   **极高：** AI 打分不准确、不公正，甚至出现逻辑荒谬的评语（典型的“幻觉”），将导致产品被弃用，并对公司声誉造成严重损害。这是项目**最大的风险**。
    -   **高：** 面试官可能直接采纳 AI 评判，放弃自己的主观判断，导致招聘偏差。
-   **替代方案：**
    -   **放弃 AI 自动打分，改为“辅助建议”。** AI 不直接生成分数，而是根据转录内容，为每个维度提供“行为示例”和“观察点建议”。例如：“在沟通能力方面，候选人使用了‘我们项目组’而非‘我’，且能清晰解释复杂技术方案。建议评分区间：4-5分。” 面试官根据建议自行打分。
    -   必须明确告知面试官，AI 的评分建议仅供参考，最终评分权在面试官手中。
-   **范围裁剪建议：** **V1 不做自动打分**。V1 仅提供“评价辅助工具”，即：AI 生成基于事实的“行为示例”和“观察点建议”。V2 或 V3 在积累大量人工打分的标注数据后，再谨慎上线 AI 打分功能，并需提供置信度标识和人工修改入口。

#### 功能四：自动生成面试报告

-   **描述：** 面试结束后，系统自动整合转录文本、重点标记、评价辅助内容，生成一份结构化的面试报告（PDF/在线文档形式），包含基本信息、对话摘要、能力评价、面试官备注等。
-   **风险：**
    -   **低：** 报告模板可能不满足所有场景。
-   **替代方案：** 提供可配置的报告模板，允许公司管理员自定义报告字段和格式。
-   **范围裁剪建议：** **V1 核心功能**。提供默认简约模板，支持导出 PDF 和在线查看。

#### 功能五：支持线上线下场景

-   **描述：** 线上面试通过集成会议 API 获取音频；线下面试通过面试官手机或电脑的麦克风录音。
-   **风险：**
    -   **中：** 线下场景录音质量受环境影响大。
    -   **中：** 线上会议 API 集成开发工作量大，且不同平台 API 稳定性不一。
-   **替代方案：** 线下场景可提供“降噪”选项。线上场景优先支持腾讯会议和飞书，其他平台（如 Zoom、Teams）在 V2 支持。
-   **范围裁剪建议：** **V1 核心功能**。优先支持线上（腾讯会议、飞书）和线下（手机 App 录音）。桌面端录音作为备选方案。

| :--- | :--- | :--- | :--- | :--- | :--- |
| **技术风险** | ASR 准确率低（口音、噪音、多人） | 高 | 高 | **高** | 1. 提供术语库；2. 增加降噪算法；3. 提示面试官控制环境；4. 提供人工编辑入口。 |

| **合规风险** | 未经候选人同意录音，侵犯隐私 | 高 | 高 | **高** | 1. 面试开始前必须有明确的“开始录音”按钮和隐私提示；2. 提供录音数据存储和删除策略；3. 确保符合 GDPR/个人信息保护法。 |

### 6. 前提条件

1.  **法律合规：** 产品上线前，必须完成隐私政策更新，明确告知用户（面试官和候选人）录音行为及数据用途。必须获得候选人明确同意（可通过面试邀请函或面试开始前的弹窗确认）。
2.  **数据安全：** 录音和转录数据必须加密存储，并提供明确的存储周期和数据删除机制。
3.  **组织就绪：** 需要在 SaaS 平台后台增加“面试助手”的开关和权限配置，允许公司管理员启用/禁用该功能。
4.  **技术就绪：**
    -   选择并接入一个高精度的云端 ASR 服务（如 Azure Speech, 阿里云语音识别等）。
    -   训练或采购一个轻量级的 NLP 模型，用于关键词提取和摘要生成。
    -   完成与腾讯会议、飞书等平台的 API 集成开发。

### 7. 用户流程（V1 版本）

1.  **面试前（HR/面试官）：**
    -   在候选人详情页或面试日程中，点击“开始 AI 面试助手”。
    -   （可选）系统弹出隐私提示，确认候选人已同意。
    -   系统自动创建一场新的面试记录。
2.  **面试中（面试官）：**
    -   **线上面试：** 在腾讯会议/飞书中开始会议。面试官在 SaaS 平台点击“开始录音”。系统自动抓取会议音频。
    -   **线下面试：** 面试官在手机 App 或桌面端点击“开始录音”。
    -   界面左侧实时显示转写文字，右侧显示“关键词高亮”区域。
    -   面试官听到重要回答时，点击转写文字旁的“标记”按钮。
3.  **面试结束（面试官）：**
    -   面试官点击“结束面试”按钮。
    -   系统自动停止录音，开始后台处理。
4.  **面试后（面试官）：**
    -   系统生成面试报告草稿，包含：转录全文、标记片段、智能摘要、评价辅助建议（行为示例）。
    -   面试官进入报告编辑页面，可以：
        -   查看、编辑、删除转录文本。
        -   查看和编辑标记。
        -   根据 AI 的“行为示例”建议，手动为各维度打分。
        -   添加自己的备注和最终评价。
    -   面试官点击“确认并归档”，报告存入候选人档案。
5.  **归档与查看（HR/面试官）：**
    -   在候选人档案中，可查看历史面试报告。
    -   支持搜索、筛选和导出。

### 8. 技术要求

-   **前端：** Web 应用（React/Vue），移动端 App (iOS/Android) 用于线下录音。
-   **后端：** 微服务架构，Python/Go 开发。
-   **AI 服务：**
    -   **ASR：** 采用云端 API（如 Azure Speech-to-Text, 阿里云语音识别），支持实时流式转写。
    -   **NLP：** 自研或调用 API 进行文本摘要、关键词提取。模型需针对招聘场景进行微调。
-   **数据存储：** 录音文件（对象存储，如 AWS S3）、转录文本和报告（结构化数据库，如 PostgreSQL）、用户数据（主数据库）。
-   **API 集成：** 腾讯会议、飞书开放平台 API。
-   **性能要求：** 实时转写延迟 < 1 秒。面试结束后报告生成时间 < 30 秒。
-   **安全要求：** 所有数据传输 HTTPS 加密，录音文件存储加密，用户权限严格控制。

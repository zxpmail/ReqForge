# 验收判据三原则（Acceptance Evidence）

> 单一出处。product-spec-builder / dev-planner / dev-builder / code-review 引用本文件，不复制全文。
> 吸收自 app-platform SDD 标准库（期望值溯源 / 强度分级 / 独立读回），按单兵规模裁剪——不新增流程门，机器强制仅一处（content-verify L1-only 拒绝，opt-in）。

## 原则一：期望值溯源（不许编造）

验收期望值必须有出处，按优先级取：

1. Product-Spec 字面量 / S0 Source 路径（`constants/`、config）
2. DEV-PLAN Primary metric（Phase 内唯一决策锚）
3. 证据文件实际内容（命令输出、测试报告）

都取不到 → 写 `[GAP: 缺什么]`，该条验收保持未决。**禁止编一个看起来合理的数**。
GAP 允许留在 spec 里；对应验收在 GAP 关闭前不得标 verified。

## 原则二：强度分级 L1–L4

| 级 | 含义 | 允许的用法 |
|----|------|-----------|
| L1 存在性 | 编译过、启动了、接口 200、文件在 | 只能当前置；禁当唯一验收 |
| L2 行为 | 断言精确期望值（数字/字面量/枚举） | 默认起步级；每 Phase ≥1 条 |
| L3 负向 | 违规输入 → 拒绝 + 拒因与 spec 逐字一致 | S0/S1（不可逆动作）必须有 |
| L4 不变量 | 操作前后守恒（成功 N 次 → 记录恰好 +N） | 高价值，防丢事件 |

写法：`- [L2] Coverage ≥ 85% (source: Primary metric)`。
标签可省略（旧行为不变）；但一个 Phase 的验收**全是 L1 = 未完成**。

## 原则三：独立读回（verify the world, not the self-report）

断言对象是世界的状态，不是 agent 的话术：

- 写后用另一条读路径核对（重跑命令、重读文件、查库），不拿写操作自己的返回值当验收
- 模型/agent 自述（「我已实现」「我读过」）不算证据

## 六禁令（判无效验收）

1. 存在性断言冒充行为断言（L1 当唯一验收）
2. mock 掉被测域自身
3. 断言镜像实现而非 spec（先看实现再定期望）
4. 写后自证（缺独立读回）
5. 改期望值迁就实现 —— 应走冲突仲裁：碰红线 → 修实现；语义等价形态不同 → 改 spec；真缺口 → 问用户
6. S1 不可逆动作无 L3 负向用例

命中任一条 = 该验收无效，按 code-review Must-fix 记。

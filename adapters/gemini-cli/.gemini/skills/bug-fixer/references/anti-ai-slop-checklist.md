# 反 AI 味清单（bug-fixer）

<!-- 交付 fix 前自检，避免敷衍式修 bug。 -->

[Anti–AI-Slop Checklist]

勾选通过后再提交 fix；任一项为「是」须补充证据或回到诊断阶段。

| 检查项 | 通过标准 |
|--------|----------|
| 凭感觉修 | 非「好像是这个问题所以改一下」——有复现步骤 + 根因追踪 |
| 症状修复 | 修了表现层而非根因（如 try-catch 吞错误而非修源头） |
| 过度修复 | 改动量 > 问题所需（修一个 null 却重构整个函数） |
| 无回归防护 | 未添加失败时能捕获此 bug 的测试用例 |
| 编造证据 | 说「测试通过」但未贴测试输出或截图 |
| 跳过复现 | 「我没能复现但我觉得修好了」——必须能复现才能确认修好 |
| 范围幻想 | 「这段修改不会影响其他模块」——无调用链分析 |
| 只修一处 | 同类型模式在代码中多处出现但只修了报告的那一处 |
